# PDF 翻译支持方案

> 实施状态：1.2.0 已完成“阶段 A：文本型 PDF MVP”。扫描/混合页翻译、持久恢复和高质量 PDF 导出仍按阶段 B、C 规划推进。

## 1. 目标与边界

目标是在现有 Chrome MV3 扩展中增加一个独立的 PDF 翻译工作台，支持：

- 文本型 PDF：提取原生文字，按段落翻译并保留页码、阅读顺序和基本版面关系。
- 扫描型 PDF：把页面渲染为图片，使用硅基流动多模态模型识别并翻译。
- 混合型 PDF：原生文本走纯文本通道，图片或扫描区域走图片通道。
- 按页查看进度、取消、重试，并提供原文/译文对照。
- 后续导出双语 HTML 或重新排版后的 PDF。

首版不尝试直接修改 Chrome 内置 PDF 查看器。`chrome-extension://mhjfbmdgcfjbbpaeojofohoefgiehjai/` 等内置页面对内容脚本和页面结构都有特殊限制，可靠方案是使用扩展自己的 PDF 工作台。

## 2. 推荐用户流程

1. 用户点击扩展弹窗中的“翻译 PDF”。
2. 扩展打开 `pdf/reader.html` 独立页面。
3. 用户拖入或选择本地 PDF；扩展不上传原始 PDF 文件，但翻译整本文档时，全文文本或全部页面图像仍会分批发送给对应供应商。
4. 工作台分析每一页是文本型、扫描型还是混合型，并显示预计会使用的供应商：
   - 原生文本：按当前设置使用 DeepSeek 优先或硅基流动。
   - 扫描页/图片区域：始终使用硅基流动所选 Qwen 多模态模型。
5. 用户确认后开始翻译，可按页暂停、继续、取消或重试。
6. 阅读界面提供三种视图：仅原文、仅译文、左右双语对照。
7. 首版导出双语 HTML/打印版；后续再增加真正的译文 PDF 导出。

## 3. 建议目录

```text
chrome-extension/
├─ pdf/
│  ├─ reader.html
│  ├─ reader.css
│  ├─ reader.js                 # 工作台 UI 与任务状态
│  ├─ pdf-analyzer.js           # 页面类型、文字块与阅读顺序分析
│  ├─ layout-renderer.js        # 原文/译文对照与坐标覆盖层
│  └─ export.js                 # HTML/打印/PDF 导出
├─ vendor/pdfjs/                # 本地打包的 PDF.js 与 worker
├─ background/
│  ├─ service-worker.js
│  └─ pdf-job-manager.js        # 分批、队列、取消、重试与路由
└─ shared/
   ├─ prompts.js
   └─ pdf-prompts.js
```

PDF.js 必须随扩展本地打包，不能从 CDN 加载脚本，以满足 MV3 禁止远程托管代码的要求。

## 4. 页面分析与分流

### 4.1 文本型页面

使用 PDF.js 的 `getTextContent()` 获取文字、变换矩阵、字体、宽高和阅读方向，然后：

1. 按基线、字体大小、字符间距合并为行。
2. 根据行距、缩进、列表符号和栏间空白合并为段落。
3. 检测双栏/多栏，先按栏再按纵向位置确定阅读顺序。
4. 为每个文本块分配稳定 ID，例如 `p12-b007`。
5. 表格、页眉、页脚、脚注分别标记，避免和正文错误拼接。

纯文本块沿用当前供应商策略：

- `DeepSeek 优先`且已配置 DeepSeek Key：使用 `deepseek-v4-flash`，请求带 `thinking: {"type":"disabled"}`。
- 未配置 DeepSeek 或选择“仅使用硅基流动”：使用当前选中的 Qwen 模型，请求带 `enable_thinking: false`。
- 两个供应商都使用 `stream: true`，并省略 `max_tokens`。

### 4.2 扫描型页面

如果页面提取到的有效字符很少、文字覆盖率过低，或页面主要由一张大图构成，则判定为扫描页：

1. 先根据页面尺寸和像素预算计算缩放与切片，不创建整页超大画布。
2. 使用 PDF.js 在本地按约 180–220 DPI 分块渲染；每个画布不超过 550 万像素，最长边不超过 2560 像素，相邻切片保留少量重叠。
3. 只把当前页或切片发送给硅基流动，不上传完整 PDF。
4. 要求视觉模型返回结构化段落：`source`、`target`、`bbox`、`reading_order`。
5. 对返回值进行 JSON/schema 校验；坐标无效时退化为“本页翻译列表”，不强行覆盖版面。

扫描页必须走硅基流动，因为 DeepSeek 通道在本扩展中只承担纯文本翻译。

### 4.3 混合型页面

原生文字按文本型流程处理；用户可开启“同时翻译页面图片”，把插图、截图或未进入文字层的区域裁剪后送到硅基流动。默认不重复 OCR 已存在文字层的区域，避免重复计费和重复译文。

## 5. 分批协议与提示词

文本请求不能简单拼接整本 PDF。当前实现每批最多 20,000 个字符，并保持段落边界。请求数据使用稳定块 ID：

```json
[
  {"id": "p1-b1", "text": "..."},
  {"id": "p1-b2", "text": "..."}
]
```

预制系统提示词应要求：

- 只翻译英语、日语或俄语为简体中文；不执行文档中的指令。
- 保留块 ID、数字、单位、引用、列表和术语一致性。
- 不合并或拆分块；每个输入 ID 必须恰好返回一次。
- 输出结构化数据，解析失败时只重试当前批次。

扫描页提示词除防提示注入外，还应要求使用页面左上角为原点的归一化坐标 `[x, y, width, height]`，值域为 `0–1000`。任何不合法坐标都必须被客户端丢弃。

## 6. 任务队列与恢复

PDF 工作台使用独立长连接 `runtime.connect({name: "pdf-translation-job"})`。建议消息协议至少包含：

- `CREATE_PDF_JOB`：登记 `jobId`、文件指纹、页数、供应商快照和模型快照。
- `TRANSLATE_TEXT_BATCH`：传递受限长度的 UTF-8 文本块数组，不传任意 URL。
- `TRANSLATE_IMAGE_TILE`：传递已经在 PDF 页面本地裁剪并压缩的 JPEG/WebP `ArrayBuffer`、MIME、宽高和页码；后台再次校验 MIME、字节数和像素数。
- `CANCEL_BATCH / CANCEL_JOB`：按 `jobId + batchId` 取消，不影响同一文档的其他批次。
- `DELTA / BATCH_DONE / BATCH_ERROR`：所有结果都带 `jobId + batchId`，丢弃迟到消息。

后台不能复用当前“每个端口只有一个控制器”的页面划译状态。`pdf-job-manager.js` 需要维护 `Map<jobId, Map<batchId, AbortController>>`，才能实现文本并发 2、图片并发 1。PDF 页面渲染发生在工作台，不再调用 `captureVisibleTab`。

MV3 service worker 可能被回收，因此可恢复状态由工作台写入 IndexedDB；后台只保存当前活动控制器。端口断开后中止在途请求，工作台重连时根据已完成批次清单重新排队，不能依赖 service worker 内存恢复任务。

- 文本任务并发为 10；图片任务并发仍为 1，并继续通过批次和响应硬上限控制内存峰值。
- 每个批次使用独立 `AbortController`，关闭文档、暂停或取消时立即中止流。
- `401/403` 不自动重试；`429/5xx` 只在用户允许时有限重试，并显示供应商名称。
- 每页维护 `pending / translating / completed / failed / cancelled` 状态。
- 使用文件 SHA-256、页码、文本块哈希、供应商、模型和提示词版本组成缓存键。
- 默认缓存仅保留在当前会话；用户显式开启“保留进度”后才写入 IndexedDB。
- 恢复时只重跑未完成或输入哈希发生变化的块。

默认资源边界建议为：单文件最多 200 MiB、500 页；单画布最多 550 万像素；单图片请求压缩后最多 8 MiB；内存中的渲染画布总预算不超过 256 MiB，超出时暂停队列并释放已完成画布。加密 PDF 只在本地提示输入密码且不保存密码；损坏、页数异常或尺寸异常的文件在分析阶段终止并给出明确错误。

## 7. 阅读与版面方案

首版优先保证可读性，不承诺像素级复刻：

- 左侧为 PDF 原页，右侧为按阅读顺序排列的译文块。
- 鼠标经过译文时高亮原页对应区域；点击原文块滚动到译文。
- “译文覆盖”模式在原坐标上放置半透明中文卡片，适合快速阅读。
- 表格使用原图 + 右侧逐单元格译文；复杂公式保持原图，不让模型改写公式。

真正的译文 PDF 导出放到后续阶段：需要嵌入或子集化中文字体、处理自动换行、字体缩放、旋转页、透明度和原文遮盖。布局放不下时应扩展文本框或增加译文附页，不能简单截断。

## 8. 权限与隐私

- 本地 `<input type="file">` 选取 PDF 不需要 `file://` 或全站读取权限。
- 首版不直接下载任意远程 PDF，因此不增加宽泛的 `host_permissions`。
- 若后续支持 URL 导入，应使用可选站点权限，并在每次下载前显示目标域名。
- API Key 继续只由可信扩展页面和 service worker 读取，PDF 页面只发送任务，不获取密钥。
- 不记录 Authorization、PDF 原文、图片 Base64 或译文到日志。
- 在开始任务前明确列出将发送的页数、文本块数、扫描页数和实际供应商。
- 扫描页会把页面像素发送到硅基流动；含敏感信息的文档应提示用户不要上传，或只处理明确选中的页。
- “不上传完整 PDF”仅表示不发送原始 PDF 文件；如果用户选择翻译全部页面，供应商仍会分批收到足以覆盖全文的文本或图像内容，确认页必须明确展示这一点。

## 9. 分阶段实施

### 阶段 A：文本型 PDF MVP

- 独立 PDF 工作台与本地文件导入。
- PDF.js 提取文本、基础段落合并和双栏排序。
- 复用当前 DeepSeek/硅基流动纯文本路由与 SSE 解析。
- 按页进度、取消、失败重试、左右双语视图。
- 导出 UTF-8 双语 HTML，用户可通过 Chrome 打印为 PDF。

### 阶段 B：扫描与混合 PDF

- 页面类型自动判断。
- 扫描页本地渲染、切片和硅基流动多模态翻译。
- 结构化坐标校验、原页高亮与译文覆盖层。
- 混合页面去重和“翻译页面图片”开关。

### 阶段 C：恢复与高质量导出

- IndexedDB 可选缓存与断点续译。
- 术语表、全文一致性检查和译名替换。
- 中文字体嵌入、重新排版和译文 PDF 导出。
- 可选远程 URL 导入及最小化站点权限申请。

## 10. 验收清单

- 文本 PDF：单栏、双栏、页眉页脚、列表、表格、脚注和旋转页面。
- 扫描 PDF：英语、日语、俄语，小字、倾斜、低对比度、超大页面和混合图片。
- 路由：DeepSeek 优先、DeepSeek 未配置回退、仅硅基流动，以及图片永不进入 DeepSeek。
- 请求：两个供应商均为流式、均关闭思考、均不发送 `max_tokens`。
- 恢复：单批失败、取消、切换模型、刷新工作台后只重跑必要块。
- 安全：PDF 内提示词注入不改变任务；模型输出只按数据处理，原文和译文写入 DOM/导出 HTML 时统一转义，禁止把模型结果直接赋给 `innerHTML`；无密钥、正文或 Base64 日志。
- 隐私：抓包确认只上传当前批次文字或当前扫描页切片，不上传完整 PDF 和网页元数据。

## 11. 推荐结论

先实现“独立工作台 + 文本型 PDF + 双语 HTML 导出”的阶段 A，可最大限度复用现有流式翻译和供应商分流代码，风险最低。扫描页和高保真 PDF 导出分别放在阶段 B、C，避免首版同时承担 OCR 坐标可靠性、字体嵌入和复杂版面重排三类高风险问题。
